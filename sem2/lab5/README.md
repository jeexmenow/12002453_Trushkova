# Лабораторная работа 5 (семестр 2). Клиент-сервер

Трушкова А.И., группа 12002453

## Цель

Получить практические навыки работы со Spring Framework: отдельное клиентское приложение запрашивает задачи у сервера по HTTP.

## Что сделано

Сервер — список дел из лабораторной работы 4, каталог `app`. К нему добавлен REST:

- `GET /api` возвращает задачи в JSON;
- клиент передаёт логин и пароль заголовком `Authorization: Basic`.

Настольный клиент на Swing лежит в `client`. Окно входа кодирует логин и пароль в Base64 и открывает список. Кнопка «Обновить задачи» снова читает `GET /api`.

Роли те же, пароль у всех: `password`.

| Логин | Роль | Что можно |
|---|---|---|
| user | USER | Смотреть список и добавлять задачи |
| editor | EDITOR | Ещё менять статус в браузере |
| moderator | MODERATOR | Ещё и удалять задачи в браузере |

В методичке `GET /api` разрешён ролям `USER` и `MODERATOR`. Здесь список и добавление доступны любой вошедшей роли, включая `EDITOR`: в браузере эта роль уже работает со списком.

## Дополнительное задание

В методичке пять пунктов, номера 18 нет. Номер 18 даёт третий пункт: `(18 - 1) mod 5 + 1 = 3`.

Из клиента можно добавить задачу: поле описания и кнопка «Добавить» отправляют `POST /api`. Сервер сохраняет задачу в PostgreSQL и ставит автором текущего пользователя. Новая задача видна и в окне клиента, и на странице в браузере.

## Запуск

Нужны JDK 21, Maven и PostgreSQL на `localhost:5432` с базой `todo_db` (пользователь и пароль `postgres`).

Сервер, из каталога `app`:

```bash
mvn spring-boot:run
```

Клиент, из каталога `client`, пока сервер запущен:

```bash
mvn exec:java
```

Страница в браузере: <http://localhost:8080/login>

## Проверка

```bash
mvn test
```

Команда запускается из `app` и использует базу `todo_db_test`. Тест проверяет, что без входа `GET /api` отвечает 401, а вошедший пользователь добавляет задачу через `POST /api` и видит её в браузере с автором.
