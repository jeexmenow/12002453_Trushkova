# Лабораторная работа 4 (семестр 2). Spring и PostgreSQL

Трушкова А.И., группа 12002453

## Цель

Получить практические навыки работы со Spring Data JPA и PostgreSQL: хранить список дел в базе, а не в памяти.

## Что сделано

За основу взят список дел из лабораторной работы 3. Проект лежит в `app`.

Подключение задано в `application.properties`:

```
jdbc:postgresql://localhost:5432/todo_db
пользователь: postgres
пароль: postgres
spring.jpa.hibernate.ddl-auto=update
```

Таблицы создаёт Hibernate при запуске. Сущность `Task` — описание и статус. Репозиторий `TaskRepository` расширяет `JpaRepository`.

Роли с прошлой работы сохранены. Пароль у всех: `password`.

| Логин | Роль | Что можно |
|---|---|---|
| user | USER | Смотреть список и добавлять задачи |
| editor | EDITOR | Ещё менять статус |
| moderator | MODERATOR | Ещё и удалять задачи |

В примере методички и статус, и удаление закрыты только ролью `MODERATOR`. Здесь смена статуса по-прежнему доступна и редактору.

## Дополнительное задание

В методичке пять пунктов, номера 18 нет. Номер 18 даёт третий пункт: `(18 - 1) mod 5 + 1 = 3`.

Добавлена таблица `app_user`: идентификатор, имя, email и пароль. Задача связана с пользователем через `user_id` (многие задачи к одному пользователю). При добавлении задачи автор берётся из текущего входа и показывается на карточке.

Класс называется `Account`, чтобы не путать его с классом пользователя Spring Security. В базе это таблица пользователей из задания.

## Запуск

Нужны JDK 21, Maven и PostgreSQL на `localhost:5432` с базой `todo_db`.

Из каталога `app`:

```bash
mvn spring-boot:run
```

Страница входа: <http://localhost:8080/login>

## Проверка

Тесты идут в отдельную базу `todo_db_test`.

```bash
mvn test
```

Тест сохраняет задачу с автором, запрещает смену статуса пользователю, разрешает её редактору и удаляет задачу от модератора.
